### 起源
用户看到《赵云与阿斗》（北京蜜獾工坊，2026 年 6-7 月霸榜微信小游戏畅玩榜/人气榜/PC 榜，IAA 变现，合成+塔防+1v1 对称对抗，单局 5-10 分钟）后，想做文字类游戏规避 AI 美术难题，考虑做成肉鸽 + Unity ECS。

### 第一轮判断（已被部分推翻）
- 活检结论：《赵云与阿斗》的护城河是「汉字即机制」（单字=单位、偏旁=攻击表现、专名=收集钩子），不是「省美术」。
- 原判断：ECS 在文字肉鸽下是过度设计（实体规模小、UI 占 60% 工、UI Toolkit 无官方 ECS 绑定）。
- 参考竞品：《Text Dungeon: The Ring of Life》（Steam 2026-09，预估 5952 wishlist / rank #5177）、乙一用 Claude Code 做的免费《Minimal Rogue》（2026-08，itch.io，MIT 开源，100 层 3-5 小时）。

### 第二轮：用户新增关键约束 → 结论修正
用户明确要「怪很多 / 曹操十万大军 / 真三国无双割草感 + 本质肉鸽」。ECS 由此获得正当理由。

**最终设计方向（待用户确认平台）**
- Fun hypothesis：用正确的字，把一整片错误的字扫成漫天笔画。
- Design pillars：数字即画面 / 一秒一个决策 / 对的时候要碾压 / 每个字死得有样子。
- 核心玩法：五行相克字——敌方字潮带五行属性（木林森/火炎焱/土城垒/金鑫锋/水淼江涛），玩家持字武器切换，相克 ×3.0、逆属性 ×0.4、切字 CD 1.5s。割草释放期 30-60s 一波，波间 20-40s 三选一构筑。
- 肉鸽层：汉字合成树（火+火=炎，炎+火=焱；木+木=林，林+木=森）天然即 build 树，中文母语者先验知识省掉教学成本。英文做不到，是真正差异化。

**关键技术判断（重要，别忘）**
- 「十万」不需要十万实体。三层 LOD：近场 0-8m（500-1500 真实体，独立字牌+笔画拆解粒子）/ 中景 8-25m（5000-15000 真实体，聚合渲染「兵 ×327」）/ 远潮 25m+（0 实体，密度场 shader）。真实实体总量 5500-16500 = ECS 甜区。十万感由 UI 击杀计数器承担（真三同屏也就几十个敌人，玩家信数字不信眼睛）。
- **不能用 TextMeshPro 逐个渲染**（一万字必崩）。必须自研 instanced text renderer：汉字预烘焙 glyph atlas（2048²/64px → 1024 字；4096² → 4096 字），BRG 或分批 DrawMeshInstanced（单次上限 1023）。文字媒介反而比 3D 更好 instancing，因为字库种类有限。
- 因此 UI Toolkit 的 ECS 集成问题被绕开——战场字走自研渲染器，UI 只剩 HUD。
- 架构：Entities + Burst + IJobEntity（16×16 网格空间分区做邻近查询，避免 O(n²)）→ NativeArray 桥接 → GPU instanced 渲染 → GPU 笔画粒子 → UI Toolkit 仅 HUD。
- 中文字形图集必须预烘焙，运行时动态生成会卡死。

**风险**：自研渲染器是最大工程量；AI 生成 200+ 词条的语感风险仍在。

**验证路径（已定义失败信号）**
1. 技术验证优先：5000 汉字 instanced demo 跑 60fps，不通过则后面全废。
2. 手感原型：固定 build 割 3 分钟。
- 失败信号 A：5000 字 <30fps → 渲染方案重做
- 失败信号 B：玩家说「只是在看数字涨」→ 反馈通道不足（加笔画密度/震屏/数字弹跳），非机制问题
- 失败信号 C：三选一时「选哪个都无所谓」→ 词条差异化不足，需重做

### 待用户确认（会改变方向的项）
1. 平台：默认假设 Steam PC。若微信小游戏，规模需砍到 1/10，设计逻辑完全不同。
2. 先做技术验证 demo 还是先写 GDD？我的建议：先跑 demo，5000 字这关过了再写文档。
3. 单局时长假设 20-30 分钟（3-4 关 × 5-8 波），若实测 >40 分钟难度曲线要重画。

### 第三轮修正：美术走序列帧
用户明确「实体都是序列帧而已，英雄单位可以是复杂一点的动画单位」。这条修正比表面更重要：
- **撤销**了第二轮「自研 instanced 文字渲染器是最大工程风险」的判断。
- 序列帧 = Unity 原生能力（Entities Graphics + sprite sheet UV 动画），无需自研 renderer。
- **关键洞察：美术难题被彻底解决**。源字形是确定的（TMP 字体资产），变换是程序化的（摆动/燃烧/笔画分离），烘焙即资产。不需要 AI 生成任何美术 → 绕开 AI 美术一致性灾难。

### 本轮挖到的三个验证坑（已同步进 `02-知识库/无头验证通道.md`）
1. **`world.Systems` 只含托管系统**（ComponentSystemBase），unmanaged `ISystem` 一个都不在里面。
   按它枚举会误判「游戏系统没挂上」。正确查法：`world.Unmanaged.GetExistingSystemState<T>()`。
2. **`cam.Render()` 离屏截图拍不到 OnGUI / IMGUI**。HUD 走 IMGUI（为免引 UGUI 包），
   所以 shot_wide / shot_close / shot_chase 里都没有 HUD。验 HUD 只能人眼看 Game 视图。
3. `mcp__unity-mcp__execute_code` 走 CodeDom，**不支持局部函数**（`void Walk(...)` 直接编译失败）；
   递归遍历得用 Queue 显式循环。
