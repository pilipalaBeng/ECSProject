# 2026-10-08 工作日志

## 实测确认：武器严格跟随英雄（HeroWeaponView）

**起因**：用户问「英雄能移动吗？还是只有武器能移动」「现在武器是跟随英雄的吗」。
上一轮我只读代码就下了结论，按验证纪律这次补了 PlayMode 实测。

**结论**：
- **英雄能移动**——WASD / 方向键。链路 `HeroIntentSystem`（读输入写 `HeroIntent.Move`）
  → `HeroMoveSystem`（推进 `Position2D` + 场地 clamp，出枪期间乘降速系数）→ `HeroView`（搬到 GameObject）。
  本次战斗改动只把组件改名 `HeroInput` → `HeroIntent`，移动逻辑一行未动。
- **武器不独立移动**——`HeroWeaponView.PlaceWeapon` 每帧重算
  `武器世界坐标 = 英雄 ECS 坐标 + forward × 前伸量 + 高度偏移`。
  它不是英雄的子节点（否则会继承英雄 GameObject 的 `(3,1,1.5)` 缩放，枪被拉成棒子），
  而是 BattleRoot 下平级节点，靠每帧重算保持贴合。

**实测证据**（PlayMode，`Logs/weapon_probe_before.txt` / `weapon_probe_after.txt`）：

| | 英雄 ECS | 英雄 GameObject | 武器 GameObject |
|---|---|---|---|
| 改前 | (0, 0) | (0, 0.12, 0) | (0.9, 0.28, 0) |
| 改后 | (18, −12) | (18, 0.12, −12) | (18.9, 0.28, −12) |

武器位移 `(18, 0, −12)` 与英雄位移**逐轴一致**，相对偏移恒为 `(+0.9, +0.16, 0)`。
这是一次 21.6 米的瞬移（远比正常移动极端），照样同帧跟上——因为是每帧重算而非父子绑定，
所以英雄瞬移/冲刺时武器不会掉队。

**输入通道确认**：`ProjectSettings.asset` 里 `activeInputHandler: 0`（旧版 Input Manager），
`manifest.json` 未装 Input System 包 → `UnityEngine.Input` 可用，键盘移动与 J/左键攻击确实生效。

## 踩到的坑（已回填 AGENTS.md「MCP 通道的第三大坑」）

`execute_code` 里**不能用 `Thread.Sleep` 等帧**——它跑在 Unity 主线程上，sleep 期间主循环完全冻结。
实测 sleep 1500ms 后 `Time.time` / `frameCount` 一字未动，得到 `heroes=0`，
看起来像「生成系统挂了」，其实只是采样时帧被自己冻住了。这个坑连续踩了两次。

同时修正 AGENTS.md 第一大坑的适用条件：**开了 `Application.runInBackground = true` 时，
窗口不在前台也照跑**（同一次实测 t 从 8.36 → 41.94、26264 帧）。

**正确姿势**：分两次调用——第一次下指令就返回，编辑器在两次调用的间隙自己推进，第二次回来采样。
