# 2026-10-09

## 血案：英雄字块被钉在世界原点（P0，已定案未修）

用户报的现象：武器自己走自己的 / 英雄不会动 / 掉血与伤害全都看不出来。
纯文件级排查（不调 unity-mcp），**根因已锁死**，不是逻辑断链，是**英雄材质选错了着色器**。

### 根因

`Mat_Glyph_Hero.mat` 的 `m_Shader` = guid `63c1aada9493fd74397e2708e6fa06c3`
= `Assets/_HanziRogue/Data/Shaders/GlyphInstanced.shader`。

那个 shader 的顶点阶段是：
```hlsl
world = _GlyphInstances[v.instanceID].Position + float3(v.vertex.x*_GlyphSize, 0, v.vertex.z*_GlyphSize);
o.pos  = mul(UNITY_MATRIX_VP, float4(world, 1.0));
```
**从头到尾没用 `UNITY_MATRIX_M`** —— 这是给 `DrawMeshInstancedIndirect` 专用写的。

而英雄是普通 `MeshRenderer` 画的：
- `SV_InstanceID` = 0 → 读 `_GlyphInstances[0]`；
- `_GlyphInstances` 只由 `InstancedEnemyRenderer` 绑到**敌人材质**上，英雄材质上从未绑过 → 读到 0。

结果：**英雄字块永远画在世界 (0,0,0)、尺寸 `_GlyphSize`=1.1m（正好一个「兵」），
跟 `HeroView` 写进去的 Transform 完全脱钩。** 武器用 `Mat_Weapon`(Unlit/Color) 吃 Transform，
于是它老老实实跟着真身跑，和钉死的字块分家。

### 证据链

| 证据 | 值 |
|---|---|
| `GlyphInstanced.shader.meta` guid | `63c1aada9493fd74397e2708e6fa06c3` |
| `Mat_Glyph_Hero.mat` 第 11 行 m_Shader guid | 同一个（`GlyphAssetBuilder.EnsureMaterial` 对英雄/敌人**都** `Shader.Find("HanziRogue/GlyphInstanced")`，只差 `enableInstancing`） |
| MainScene.unity:772 Hero 的 m_Materials | `bfd98c92…` = Mat_Glyph_Hero |
| MainScene.unity:638 InstancedEnemyRenderer.glyphMaterial | `1ef93da8…` = Mat_Glyph_Bing（缓冲区只绑这个） |
| 截图英雄字块墨迹实测 | 18×16 px = **0.98×0.87 m**（1.1m quad 的墨迹占比 0.9×0.8 ⇒ 预测 18.1×16.1 px，**精确吻合**） |
| 若尺度正确本该是 | 3.0×1.5 m ⇒ 墨迹 ~49×25 px |
| 截图武器实测 | 33×2 px = 1.8×0.12 m，与 Mat_Weapon 尺寸精确吻合 ⇒ 定标 18.33 px/m |
| 武器↔英雄字块距离 | 7.23 m ⇒ 英雄真身离世界原点约 6.4~6.7 m |

### 副产物结论

- **输入链是好的**：英雄 ECS 位置离原点 6.4m，只有 `HeroIntentSystem` 读键盘才会动 ⇒ 输入桥没问题。
- HUD 看不到是**截图裁切**，不是 bug：`HudController.OnGUI` 无条件画帧率/按键提示；
  按 18.33 px/m 反推游戏窗口约 1172×659（orthoSize 18 ⇒ 纵向 36m），截图是中间 385×259 的裁切，
  左上角 (12,12) 的 HUD 被裁在外面。
- 兵潮那层**整齐点阵**是正常的：1000 个兵按 SeparationRadius 1.15 密堆 = 半径约 15.5m 的一坨，
  相机在坨内部，所以整屏看起来是均匀字格。
- 两个 SmokeTest 都是 `SetHeroIntent` 直写意图 + 不渲染，所以**表现层零覆盖**，这类 bug 自检抓不到。

### 修法（待用户拍板，未动手）

新增 `Assets/_HanziRogue/Data/Shaders/GlyphFlat.shader`（`HanziRogue/GlyphFlat`）：
Properties 与 GlyphInstanced 完全对齐（`_MainTex/_Color/_FlashColor/_Cutoff`），
但顶点用 `UnityObjectToClipPos(v.vertex)`，frag 用 `tex2D(_MainTex,i.uv)*_Color` + `clip(c.a-_Cutoff)`，
**必须 `Cull Off`**（俯视看的是 quad 背面，同 GlyphInstanced 注释里那条坑）。

然后 `GlyphAssetBuilder` 里把 shader 名参数化，英雄走 `HanziRogue/GlyphFlat`。
因为 `EnsureMaterial` 每次都会无条件 `material.shader = Shader.Find(...)`，
所以**跑一次 `HanziRogue/Build Minimal Scenes` 就会自动修正 Mat_Glyph_Hero.mat**，不用手改资产。

修好后英雄字块会是它本该的 3.0×1.5 m（`SceneBuilder.CreateHero` 的 glyphSize 1.5 × 2），
比现在大 3 倍；`HeroWeaponView.ApplyHeroTint` 的闪红也会第一次真正落在能看见的地方。

## 已实施（用户「你来改吧」放行）

### 像素取证的第二轮修正（重要）

第一轮把「金色块」和「亮条」的方位读反了，绕了一圈。第二轮用连通域重测 + 4x 放大目视后定案：

- 金色块（英雄材质色族）连通域集中在 `(197,116)-(211,130)` = **15×15 px ≈ 1.1 m** —— 和「兵」一样大，坐实「被钉在原点且用 `_GlyphSize`」。
- 亮条（`Mat_Weapon` 色 `(224,214,158)` 逐分量精确命中）单连通域 `33×2 px`；长度 1.8 m ↔ 33 px、厚度 0.12 m ↔ 2 px，**两个独立维度自洽** ⇒ 18.33 px/m 标定可信。
- **决定性线索**：亮条周围有一圈明显的**兵字空地**——那是 `StopRadius`(1.5 m) 的内侧空洞 ⇒ **亮条所在处才是英雄真身**，字形被钉在 7.0 m 外。
- 之前的困惑（「金色块看着在裁剪图中心附近、相机该在原点」）源于**误以为截图是以游戏窗口中心裁的**。截图只是任意区域的裁剪，图像中心 ≠ 窗口中心。去掉这个错误前提后，一切自洽：相机跟随正常，真身在 `(-7.0, +1.9)`。
- `look_full4x.png` 里还能看到地面网格线，只是 `_LineColor` 与 `_BaseColor` 明度差太小、几乎看不见（调参问题，非缺陷）。

**结论不变，且只剩一个 bug**：相机跟随好的、武器落位对的、输入/伤害/兵销毁/英雄阵亡判据全部正常（`CombatSmokeTest` 8 项本就 PASS）。
