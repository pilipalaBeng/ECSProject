# 开发规则总纲

> **L1 按需加载**。宪法 §3 架构铁律的执行细则。写代码前读，改完对照自查。
> 版本 v0.2 · 2026-10-07 · 路径与目录改引 `工程事实.md`（ADR-0007）
>
> **性质**：本文件是编码细则（指南层）。硬边界在 `CONSTRAINTS.md`，数值在 `数值预算表.md`。

## 1. 程序集与目录

```
Assets/_HanziRogue/          路径主源见 01-治理/工程事实.md §2
├── Core/                    核心层：配置、空间分区、数据定义
├── Gameplay/                玩法层：ECS Systems
├── Presentation/            表现层：渲染、特效、HUD
└── Editor/                  编辑器工具：AtlasBaker 等
```

**依赖方向（单向，违反即违规）**：

```
Core  ←  Gameplay  ←  Presentation
Core  ←  Editor
Gameplay ← Editor
```

- `Core` **不得**引用 Gameplay / Presentation
- `Gameplay` **不得**引用 Presentation（逻辑不认识表现）
- `Presentation` 可引用 Core + Gameplay（只读数据）
- 命名空间：`HanziRogue.Core.*` / `HanziRogue.Gameplay.*` / `HanziRogue.Presentation.*` [待定]

## 2. ECS 编码细则

### 2.1 Component 定义

| 规则 | 说明 |
|------|------|
| 只用 `IComponentData`（unmanaged） | 需要 class/string 的地方走 `IComponentData` 存索引 + 查表 |
| 禁 managed 类型 | class / string / 数组 / 委托 / `NativeArray`（放 System 里） |
| 字段顺序按大小排列 | 减少内存对齐浪费（热路径实体量大，对齐损失会被放大） |
| 一个 Component 一个职责 | 避免"万能组件"拖垮 chunk 利用率 |

### 2.2 System 编写

| 规则 | 说明 |
|------|------|
| 优先 `IJobEntity` / `IJobChunk` | 不用 `SystemAPI.Query` 在主线程跑万级循环 |
| `[BurstCompile]` 必须加 | 除非明确需要 managed 交互（此时写明理由） |
| 禁 `EntityManager` 结构性变更于 Job 内 | 用 `EntityCommandBuffer`，且指定 playback 时机 |
| 一个 System 一个职责 | 函数名即职责，函数名超过 20 字说明职责不清 |

### 2.3 热路径禁令（每帧万次，违反即 Bug）

```
✗ new / 对象分配          ✗ 闭包捕获
✗ LINQ                    ✗ string 拼接 / ToString()
✗ GameObject.Find 系列     ✗ GetComponent<T>()
✗ Dictionary 查找（改 NativeHashMap）
✗ 装箱 / foreach 于非 native 集合
```

### 2.4 邻近查询

- 一律走 `SpatialGrid`（16×16，[待实测] 分辨率）
- **禁止** O(n²) 全量遍历（CONSTRAINTS C1.8）
- 网格分辨率是 tuning lever，写进配置，不写死在代码里

## 3. 配置资产管理

| 规则 | 说明 |
|------|------|
| 数值一律进配置资产 | 禁代码内硬编码魔数 |
| 规模常量集中 | `ScaleConfig`：实体上限 / LOD 距离 / 批次上限（C5.6） |
| 字库数据集中 | `WordDatabase`：五行 / 层级 / 帧数 / 基础数值 |
| 相克表集中 | `WuxingTable`：五行关系与倍率 |
| 数值带 rationale | 配置资产内每个数值必须有注释说明"为什么是这个数"，无则标 `[PLACEHOLDER]` |

---

## 4. 表现层规则

| 规则 | 说明 |
|------|------|
| Presentation 只读 Gameplay 数据 | **禁止回写**。回写需求 = 架构问题，走 ADR |
| 战场文字走 instanced 渲染 | 禁 TMP 逐字渲染（C4.1） |
| 图集 Editor 预烘焙 | 禁运行时生成（C2.6） |
| 单次 instancing ≤1,023 | 超出分批（C4.3） |
| HUD 走 UI Toolkit | 不与 Entity 双向绑定（C4.7） |
| 名将走 Hybrid | Entity 逻辑 + GameObject 表现，数量 ≤8 |

## 5. 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| Component | 名词，无前缀 | `Position`、`WordElement`、`Hp` |
| System | `<职责>System` | `DamageSystem`、`CounterSystem` |
| Authoring | `<Component>Authoring` | `WordTideAuthoring` |
| Job | `<动作>Job` | `ApplyDamageJob` |
| 配置资产 | `<Domain>Config` / `<Domain>Database` | `ScaleConfig`、`WordDatabase` |
| 事件 | `<主体><动作>Event` | `WaveClearedEvent` |

## 7. 与 GrumpyGrandma 项目的差异（别照搬）

| 项 | GrumpyGrandma | HanziRogue |
|----|---------------|------------|
| 架构 | ServiceLocator + EventBus（OOP） | ECS/DOTS（数据导向） |
| 单位规模 | 个数 | 万级 |
| 表现 | SpriteRenderer / Animator | Instanced sprite sheet |
| 事件 | C# event / EventBus | EntityCommandBuffer + Native 容器 |
| 数值载体 | ScriptableObject | ScriptableObject + ECS Component |

**不要**把 GrumpyGrandma 的 OOP 模式（如 MonoBehaviour 上挂组件、Inspector 拖引用）直接搬过来——两者心智模型不同。
