# 约束清单（Constraints）

> **效力**：L0 常驻。本文件是宪法 §2/§3 的可执行化硬边界。
> 每条约束都能被机器或人工检查；违反即 Bug，不是「风格问题」。
>
> **性质声明**：本文件**只承载硬不变量**（invariant）。可调数值一律在 `数值预算表.md`，工程事实一律在 `工程事实.md`——改那两份不走修订程序，改这份必须走 ADR。
>
> **版本**：v0.2 · **批准日期** 2026-10-07 · **最近修订** 2026-10-07
> **版本语义**：MAJOR = 删除或反转某条约束；MINOR = 新增约束或收紧既有约束；PATCH = 措辞澄清
> **状态标记**：✅ 已确定 / ⚠ 依赖未定项 U1（平台）/ [待实测] 数字未经验证
> **检查列约定**：`自动` = 编译期 / asmdef / 自检脚本 / Editor 校验可拦；`人工` = 需评审或 Profiler 观察

**v0.2 变更**：删除原 C6 数值段（迁至 `数值预算表.md`）；每条补「检查」列并标注自动化程度（ADR-0007）。

## C1 · 规模与性能约束 ⚠

| 编号 | 约束 | 值 | 理由 | 检查 | 违反后果 |
|------|------|-----|------|------|----------|
| C1.1 | 真实模拟实体硬上限 | **16,500** | ECS+Burst 甜区；超过后帧时间非线性上升且收益递减 | 自动 | 掉帧、发热、小游戏直接崩 |
| C1.2 | 字潮层实体区间 | 5,000 - 15,000 | 中景聚合渲染的承载量 | 自动 | 见 C1.1 |
| C1.3 | 近场独立实体区间 | 500 - 1,500 | 需要独立动画与独立击杀反馈的量 | 自动 | 超出则特效噪声淹没信息 |
| C1.4 | 精锐层实体区间 | 50 - 200 | 中等复杂度单位 | 自动 | — |
| C1.5 | 名将层实体区间 | 1 - 8 | Hybrid 表现层，走 GameObject | 自动 | 超出性能无意义 |
| C1.6 | 远潮层实体数 | **0**（纯 shader 密度场） | 不模拟视野外的个体 | 人工 | 违反即等于突破 C1.1 |
| C1.7 | 性能门（Steam PC 假设） | 12,000 实体下 **≥60fps** | 割草手感依赖流畅度，掉到 30 即「卡」 | 人工 | 手感原型失败信号 A |
| C1.8 | 邻近查询复杂度 | 必须 ≤ O(n·k)，k 为邻域常量 | 空间分区网格 | 人工 | O(n²) 在万级必然崩 |
| C1.9 | 最小闭环阶段实体数 | **5,000**（阶段值，**非目标值**） | 低于 C1.1 上限，给调试留余量；正式目标值待 U1 确定后再定 | 自动 | 把阶段值误当目标值，会锁死规模设计 |

⚠ **C1.1 / C1.2 / C1.7 依赖 U1（平台）**：若最终为微信小游戏，整体上限需下调至 **3,000-5,000**，性能门改为 **≥30fps**。

⚠ **C1.1 / C1.2 / C1.7 与 N4.6（竞技场 ±50 米）在几何上不自洽，待拍板**（ADR-0012 实测）：±50 米场地、1.15 米字间距的物理容量只有 **6,858**。而 C1.7 的性能门写着 12,000 实体（需半径约 66 米）、C1.2 上沿 15,000（约 74 米）、C1.1 上限 16,500（约 77 米）——**都超出场地两倍以上面积**。超容量的症状不是掉帧，是字直接压成一坨糊掉（实测 10,000 实体时字间距从设计 1.15 米塌到 0.016 米）。唯一自洽的是 **C1.9 的最小闭环阶段值 5,000**（占用 0.73x，健康）。三条出路：放大 `FieldSize` / 缩小 `SeparationRadius` / 下调规模数字。详见 **ADR-0012**。

**检查方式**：C1.1-C1.5、C1.9 由 `ScaleConfig` 集中定义 + 运行时 HUD 显示当前实体数与帧时间，超界即报警；C1.6/C1.8 走代码评审（看是否走 SpatialGrid）；C1.7 必须给实测数字（实体数 + 帧率 + 是否开 Burst）。
**主源声明**：本段是规模数字的**唯一主源**。`ADR-0002` 与 `02-知识库/ecs-规模与渲染.md` 中的同类数字均为引用。

## C2 · 图集与内存约束 ✅

| 编号 | 约束 | 值 | 理由 | 检查 |
|------|------|-----|------|------|
| C2.1 | 单字尺寸 | 64×64 px（RGBA = 16 KB/帧） | 分辨率够看，内存可控 | 自动 |
| C2.2 | 字潮序列帧数 | **4-6 帧**循环 | 摆动/冲锋循环，帧数越多图集越大 | 自动 |
| C2.3 | 精锐序列帧数 | **8-12 帧**（含受击、死亡） | 需要独立死亡表现 | 自动 |
| C2.4 | 名将序列帧数 | **24+ 帧**，多段招式 | 数量少（≤8），可以奢侈 | 自动 |
| C2.5 | 图集总内存上限 | **≤ 80 MB**（运行时常驻） | 500 字 × 8 帧 × 16 KB ≈ 65 MB，留余量 | 自动 |
| C2.6 | 图集必须预烘焙 | Editor 阶段生成资产 | 运行时动态生成会卡死主线程 | 自动 |
| C2.7 | 图集按关卡流式加载 | 一波实际只出现 3-5 种字 | 进一步压常驻内存 | 人工 |

**违反后果**：内存爆 / 加载卡顿 / 移动端直接闪退。
**检查方式**：烘焙脚本输出图集尺寸与体积入档；Profiler 内存快照比对 C2.5；C2.6 由「无运行时生成调用」评审确认。

## C3 · 字库约束 ✅

| 编号 | 约束 | 值 | 理由 | 检查 |
|------|------|-----|------|------|
| C3.1 | 总字库上限 | **500 字**（宪法 §2.4 硬封顶） | 由 C2.5 反推 | 自动 |
| C3.2 | 首发字库建议区间 | 200 - 350 字 | 留扩展空间，同时保证每字有存在感 | 人工 |
| C3.3 | 字形源唯一 | 全部来自同一套 TMP 字体资产 | 宪法 §2.3；多源 = 风格不一致 | 自动 |
| C3.4 | 生僻字处理 | 必须确认字体覆盖，缺字走 fallback 字体链 | 合成字（焱/淼/鑫）可能不在常用字库 | 自动 |
| C3.5 | 每个字必须有玩法身份 | 字 = 五行属性 + 兵种/效果 | 无身份的字不许进库（凑数字会稀释记忆点） | 自动 |

**检查方式**：字库登记表（见 `02-知识库/汉字机制库.md`）逐字登记属性，无属性即违规；`WordDatabase` 校验脚本检查每字五行 + 层级非空。

## C4 · 渲染约束 ✅

| 编号 | 约束 | 值 | 理由 | 检查 |
|------|------|-----|------|------|
| C4.1 | 禁止用 TextMeshPro 渲染战场实体 | 强制 | TMP 逐字渲染在万级必然崩 | 人工 |
| C4.2 | 字潮/精锐走 GPU instancing + sprite sheet UV 动画 | 强制 | 单批次可绘制数千 | 人工 |
| C4.3 | 单批次数上限 | **1,023**（`DrawMeshInstanced` 硬限），需分批 | Unity API 限制 | 自动 |
| C4.4 | 名将层走 Hybrid（Entity 逻辑 + GameObject 表现） | 允许 | 数量 ≤8，性能无压力 | 自动 |
| C4.5 | 击杀特效走预烘焙序列帧 | 完整→裂开→笔画飞散→消散，**6 帧** | 比实时笔画粒子系统便宜一个数量级 | 自动 |
| C4.6 | 近场播完整碎裂动画，中景走简化版 | 淡出 + 计数跳字 | 中景播全套 = 噪声 | 人工 |
| C4.7 | HUD 走 UI Toolkit，不与 Entity 双向绑定 | 强制 | 宪法 §3.4 | 人工 |

**检查方式**：C4.3 在渲染分批代码里断言；C4.1/C4.2/C4.6/C4.7 走 Frame Debugger 观察 draw call 与评审。

## 约束变更

修改任何约束 = 修改硬边界，必须：

1. 走 ADR（标题前缀 `[约束变更]`）
2. 同步更新本文件与宪法受影响条款
3. 版本号按本文件头部「版本语义」递增，并更新「最近修订」日期
4. 若某条约束从 `人工` 检查升级为 `自动` 检查（如补了 Editor 校验脚本），同步更新该行「检查」列
