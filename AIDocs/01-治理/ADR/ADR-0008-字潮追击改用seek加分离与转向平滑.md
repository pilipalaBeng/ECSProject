# ADR-0008: 字潮追击改用 seek + separation + 转向平滑（放弃 Boids 聚合 / 对齐）

> **状态**：已采纳（待验证回填）
> **日期**：2026-10-07
> **决策者**：扣丢桑（反馈「追溯算法不是很好」）+ AI（方案与实施）
> **影响范围**：`BoidsSystem` / `Components.GameConfig` / `ScaleConfig` / `EnemySpawnSystem` / `BoidsSmokeTest`

---

## 背景（Context）

最小闭环里的敌人集群用**经典 Boids 四力**：分离 1.6 / 聚合 0.5 / 对齐 0.8 / 追击 2.2，
速度用**加速度积分**（`vel += accel * dt`，无阻尼项）。

用户反馈「追溯算法不是很好」。对照幸存者类（Vampire Survivors / 弹壳特攻队同类）的公开实现：

| 来源 | 做法 |
|------|------|
| Construct 社区（2022）复刻讨论 | VS 敌人「move as Bullet」——朝玩家直线匀速；重叠问题靠「simple push」解决，不寻路 |
| GitHub 上的 C++ 复刻 | `dir = normalize(player - pos); pos += dir * moveSpeed` —— 纯 seek，四行代码 |
| GameMaker 复刻教程 | "For that we only need a direction where to go and a speed value" |
| 中文 Unity 复刻复盘 | 明确指出「每帧直接把速度朝玩家方向拉会**集体抽搐式转向**」，需限制转向角速度（turnSpeed 3~5 弧度/秒），且 `velocity = newDir * moveSpeed`（**直接设速度，不是积分**） |

结论：**幸存者类不做寻路、不做群体自组织**，追击就是 seek + 防重叠 + 转向平滑三件事。

约束条件不变：宪法 C1.8（邻域查询必须走空间分区，禁止 O(n²)）、C5.6（数值集中）、C2（一万个字要能跑）。

---

## 备选方案（Options）

| 方案 | 优点 | 缺点 | 成本 |
|------|------|------|------|
| A. 保留四力 Boids，只调权重 | 改一个数字，零风险 | 治标。聚合/对齐本身就会造成盘旋，权重调小只是减轻，调大方向仍然错 | 极低 |
| B. 聚合/对齐归零，保留加速度积分 | 去掉盘旋主因 | 仍无阻尼 → 过冲、漂移；玩家移动时集体抽搐 | 低 |
| **C. 聚合/对齐归零 + 转向速率限制 + 直接设速度 + 分离按距离衰减 + 速度随机化** | 与幸存者类一致；观感从「围着你转」变「扑上来」 | 彻底失去 Boids 自组织形态（将来要做雁阵/鱼群得另开一套） | 中 |
| D. 引入流场寻路（flow field） | 可处理障碍物绕行 | 战场是空旷平面、无遮挡，完全用不上；一千个单位建流场是纯浪费 | 高 |

---

## 决策（Decision）

**选择方案 C。** 具体四点：

1. **聚合 / 对齐权重默认 0**——字段保留，不为零时仍然生效，方便随时 A/B 对比。
2. **去掉加速度积分**：期望方向 `desired = normalize(seek + separation)`，
   当前朝向以 `TurnRate`（5 弧度/秒）为上限朝 desired 转，`vel = dir * speed`。
3. **分离力不再归一化**：改为按 `(1 - d/r)` 线性衰减，越近推得越狠、到边缘衰减为 0。
4. **每个兵速度 ±12% 随机**：复用已有的 `MoveSpeed` 组件（生成时写不同值），不新增组件。

**为什么原来是错的**（这是本 ADR 的核心）：

- **聚合 + 对齐是给鸟群用的**，不是给「追杀玩家的敌人」用的。敌人有唯一目标，
  这两项会让群体趋向绕着目标**盘旋**而不是扑上来。
  上一轮取证截图里观察到的「旋臂结构」不是玄学，就是它——当时误判成了观感问题。
- **加速度积分没有阻尼**：敌人会冲过头再绕回来，观感是漂移、绕圈，不是咬人。
- **分离力 `normalizesafe` 后丢掉了距离信息**：只要有一个邻居就全力推开 → 来回抖。
- **全场同速**（8 m/s 一个不差）：一千个字像一块刚性板整体平移，看不到「字潮」的层次。

---

## 后果（Consequences）

### 正面

- 观感从「围着玩家转圈」变成「扑上来咬」，贴合幸存者类的压迫感来源
- 转向平滑消除了玩家移动时的集体抽搐（一千个字同时掰方向）
- 速度差异让字潮有前后层次，前排快后排慢，自然形成「浪」
- 聚合/对齐关闭后，邻居查询里质心与平均速度的累加直接跳过——不为零成本的东西付账

### 负面 / 需要接受的代价

- **彻底失去 Boids 的群体自组织形态**。将来若要做「雁阵」「鱼群」这类非追击字群，
  需要另开组件，不在本决策范围内
- 分离力存在时，高密度区仍会压字（属手感调优，不是 bug）
- `TurnRate` 目前是 `[PLACEHOLDER]`：3~5 取自他人复刻的实测区间，本项目尚未手感对照

## 复核条件（何时重新评估）

- 战场引入**障碍物**时——届时 seek 不再够用，需要回到流场（方案 D）
- 要加入**非追击型字群**（雁阵、鱼群、围观群众）时——需要自组织，本决策不适用
- 实体规模上到 5000+ 且单帧逻辑耗时成为瓶颈时——转向平滑的 acos/sin/cos 是可优化项
