# ADR-0017: 命中判定必须与所见一致——枪身胶囊 + 贴身圆两段判定

> **状态**：已采纳
> **日期**：2026-10-10
> **决策者**：扣丢桑（报「英雄跟随移动了，但武器碰到小兵之后没有掉血」）
> **影响范围**：`CombatBalance`（新增 `HeroPointBlankRadius`）、`CombatConfig`（数值与 Tooltip）、`Data/CombatConfig.asset`、`Gameplay/HeroAttackSystem`（命中形状）、`Presentation/HeroWeaponView` + `Editor/SceneBuilder` + `Scenes/MainScene.unity`（枪身长度与姿态）、`Presentation/HudController`（攻击状态读数）、`Editor/CombatSmokeTest`（用例 1 / 3 / 9）
> **关联 Spec**：`数值预算表.md` §5（N5.1 / N5.4 / N5.5 / N5.8 / N5.13 / N5.14）

---

## 背景（Context）

上一轮（ADR-0015/0016）修好「英雄字块钉在原点」之后，用户报：

> 英雄跟随移动了，但是**武器碰到小兵之后没有掉血**。

这次没有再怀疑伤害链——它由 `CombatSmokeTest` 的 8 项断言证明是通的（含「两下致死」「兵反击」「阵亡」）。取证改成**读玩家屏幕上真实发生的事**：从截图左上角 HUD 抠出「剩余兵 1000 / 1000　**击杀 0**」——一次命中都没有发生过。

那么问题只可能在「判定体积」上。逐条量出来：

| 事实 | 数值 | 后果 |
|------|------|------|
| 兵停在哪 | `ScaleConfig.StopRadius = 1.5 m`（硬核 `HeroCoreRadius = 0.9`） | 兵稳定停在距英雄中心 1.5~2.5 m 的环带上 |
| 「英雄」二字多大 | `HeroView` scale (3, 1, 1.5)，glyphSize 1.5 → **半宽 1.5 m** | **停在 1.5 m 的兵，字面就压在英雄身上** |
| 判定带多宽 | `HeroAttackHalfWidth = 0.55` | 在 1.5 m 处只覆盖 **±20°** |
| 兵怎么分布 | 间距 1.15 m ≈ 在 1.5 m 环上 **44°** 一个 | 字潮是**离散密堆**：±20° 的带里经常一个字都没有 |
| 刀身画到哪 | scale z = 1.8，`thrustDistance = 2.4` → 尖端 **3.3 m** | 刀尖越过判定线（`Reach = 2.6`）的那一段「看得见、打不到」 |
| 朝向是什么 | `HeroFacingSystem`：朝向 = **移动方向** | 英雄 14 m/s > 兵 8 m/s，跑起来时朝向指向空地，追兵全在身后 |

**结论：伤害链是通的，坏掉的是「判定体积与所见不是同一个东西」。** 玩家看到枪压在字上 ⇒ 认为碰到就该掉血；而代码只认「朝向前方 ±0.55 m 的长条、且只在 18 帧里的 1 帧」。两件事从来没有对齐过。

这类故障极难查，因为它**不报错、不自检失败、静态检查全过**，表现还和「功能没实现」一模一样。

## 备选方案（Options）

| 方案 | 做法 | 判断 |
|------|------|------|
| A. 只把 `Reach` 调大 | 2.6 → 3.6，让刀尖落在判定边界上 | ⚠️ 必要但不充分。贴身那些「不在朝向上」的字照样免疫，跑动时那条带照样指向空地 |
| B. 攻击时**自动对准最近的兵** | 新增 `HeroAimSystem`：停下攻击时朝向最近的兵 | ⚠️ 能治「跑动时朝向指向空地」，但要新增一个每帧扫全场的系统（或引入同步点），而且**改的是操作手感**——用户没要求 |
| C. 改成 360° 全向判定 | 只要在半径内就掉血 | ❌ 突刺动画会撒谎（背后的字凭空死），枪刺的「一条线」味道全丢 |
| D. 拉长刀身 + 加宽判定 + **新增贴身圆**（不看朝向） | 三段一起对齐 | ✅ 见下 |

## 决策（Decision）

**D。判定改成两段的「或」，并把三条对齐不变式写死。**

### 1. 命中形状：枪身胶囊 ∪ 贴身圆

```csharp
// CollectHeroHitsJob.IsHittable
if (math.lengthsq(toEnemy) <= PointBlankRadiusSq) return true;      // ② 贴身圆：不看朝向
float along = math.dot(toEnemy, facing);
if (along < 0f || along > Reach) return false;                       // ① 枪身胶囊
return math.lengthsq(toEnemy - facing * along) <= HalfWidth * HalfWidth;
```

**贴身圆的物理直觉**：枪托、枪身、胳膊都在那个半径里。更关键的是**几何事实**：兵停在 1.5 m，而英雄字半宽 1.5 m——那些兵本来就画在英雄身上，对它们谈朝向没有意义。

用**直线距离**排序而不是沿枪线的投影：贴身那一档会出现负投影，混进排序会让背后的字抢到最前面的槽位。

### 2. 三条对齐不变式（写进 Tooltip 与自检）

| 不变式 | 当前取值 | 破掉的后果 |
|--------|----------|------------|
| `HeroReach = HeroWeaponView.thrustDistance + 刀身半长` | `3.6 = 2.2 + 1.4` | 刀尖越过判定线 → 看得见打不到（本次事故） |
| `HeroAttackHalfWidth ≥ 一个「兵」字宽` | `1.1 ≥ 1.1` | 窄到字与字的缝里，判定带经常空着 |
| `ScaleConfig.StopRadius < HeroPointBlankRadius < 「背后的兵」的用例距离` | `1.5 < 1.8 < 2.0` | 下限破了贴身圆形同虚设；上限破了会把自检用例 2 的「背后不掉血」一起打掉——那是「不是横扫」的唯一护栏 |

### 3. 数值调整（本轮）

| 项 | 旧 | 新 | 依据 |
|----|----|----|------|
| `HeroMaxHealth` | 100 | **200** | 用户指定翻倍 |
| `HeroReach` | 2.6 | **3.6** | 对齐刀尖 |
| `HeroAttackHalfWidth` | 0.55 | **1.1** | 一个字宽 |
| `HeroPointBlankRadius` | — | **1.8** | 新增，见不变式 |
| `HeroPierceCap` | 2 | **3** | 枪变长变宽后，一串扎穿三个才看得出「穿」 |
| `HitFlashDuration` | 0.12 | **0.16** | 闪白是这套战斗唯一的即时反馈；0.12 s = 7 帧，混在 1000 字里抓不住 |
| 刀身长度 / 姿态 | `1.8`，`0.9/0.55/2.4` | **`2.8`**，**`1.4/0.9/2.2`** | 用户要求「武器再做长一些」+ 对齐 `Reach` |

### 4. 自检补一条用例（用例 9）

「贴身半径内的兵不看方向也挨打」：把一前一后两个兵都摆在 1.2 m（都在英雄字底下），断言**两个都掉血**。背后那个只能靠贴身圆命中——它掉血才说明规则生效。

### 5. HUD 增加攻击状态读数

`突刺 J：未按 / 蓄势 / 出枪（判定帧）/ 收枪`。

理由：这个项目连着两轮把时间花在「玩家以为在攻击、其实按键或相位没进去」上，而这两种故障在画面上**完全一样**（枪该动还是动）。把它摊在屏幕上，一眼分清是输入层还是逻辑层。表现层只读不写（宪法 §3.1）。

### 6. 场景文件同步

`HeroWeapon` 的 `m_LocalScale` 与 `HeroWeaponView` 的 `restDistance / chargeDistance / thrustDistance` 是**序列化在 `MainScene.unity` 里的值**，改 C# 默认值不会影响已有场景（ADR-0016 同一课）。因此两处都已手改落盘。

## 后果（Consequences）

### 正面

- **「看着碰到」与「真的掉血」第一次是同一件事**：贴身圆负责压在身上的字，加宽的胶囊负责前方那一条字列。
- 不变式全部写进 Tooltip + 自检：下次改枪长/枪位，用例 9 会在无头自检里当场报出来。
- 攻击是否生效**肉眼可自证**（HUD 的相位读数 + 兵闪白 0.16 s）。

### 负面 / 需要接受的代价

- **`HeroReach` 3.6 > `EnemyAttackRange` 2.0**：英雄现在明显比兵够得远。这是刻意的（长枪对拳头的兵种差异），但若将来要让兵有威胁，得回到 `数值预算表.md` §5 重新配一次。
- **贴身圆是一层「不看方向」的判定**，天然带一点 AoE 味。它被 `PierceCap = 3` 限住（每 0.3 s 最多 3 个），不是全向割草；但如果将来把 `PierceCap` 放大，它会先变成 AOE。
- **枪身变长后 `restDistance` 从 0.9 提到 1.4**：常态下枪不再「握在字心」，而是整根悬在字外面——观感变化需要真机复核（`数值预算表.md` 已标 `[PLACEHOLDER]`）。
- HUD 多一行读数，`OnGUI` 每帧多两次 `ToComponentDataArray`。1k 实体量级可忽略；若将来 HUD 成为瓶颈，把这几项合并成一次查询。

## 复核条件（何时重新评估）

- **玩家仍然觉得「碰到却不掉血」** → 说明问题不只是判定体积，回去查输入层（HUD 的 `突刺 J` 读数就是为这个留的取证口）
- **`PierceCap` 再往上调** → 贴身圆会先变成全向 AOE，需要重新设计命中形状而不是继续加数
- **兵种开始分化（精锐兵 / 远程兵）** → 贴身圆的物理直觉（枪托也在身上）仍然成立，但要复核它是否让「贴脸」变成唯一正解
